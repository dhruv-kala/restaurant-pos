# Task 30.4 - Tax Calculation Engine

## Status

Complete.

## Objective

Implement deterministic tax calculation for orders, bills, receipts, and future customer ordering.

## Scope

Implemented:

- tax calculation service
- inclusive/exclusive tax support
- tax breakdown generation
- tax calculation snapshot

Not implemented:

- tax filing
- government reporting
- accounting export
- shared Flutter clients
- tax UI

## Ownership

- tax calculation
- tax breakdown
- tax snapshots
- calculation explainability

## Inputs

- tenant
- outlet
- order/bill items
- item category
- tax profile
- tax group
- businessDate
- customer tax context if available

## Invariants

- Calculation must be deterministic.
- Finalized bills store snapshots.
- Historical bills are not recalculated from live rules.
- Tax calculation must return explainable breakdowns.
- Tenant isolation is enforced.

## Dependencies

Requires:

- Task 30.1
- Task 30.2
- Task 30.3
- Orders
- Billing
- Receipts

## Implementation Summary

- Added `TaxCalculationSnapshot` as an append-only, tenant/outlet-scoped
  snapshot table with forced RLS.
- Added `POST /tax/calculate` for protected tax calculation previews.
- Added `TaxCalculationService` with fiscal policy context, active/default tax
  profile resolution, and item/category/tenant-default rule precedence.
- Used integer minor-unit arithmetic and basis-point rates for deterministic
  exclusive and inclusive tax calculation.
- Generated explainable line, component, and bill-level tax breakdowns.
- Wired new bill generation to calculate tax from current tax rules and persist
  immutable calculation snapshots linked to the generated bill/order.

## Completion Criteria

- Tax calculation works.
- Inclusive and exclusive tax supported.
- Bill tax snapshots created.
- Build passes.
