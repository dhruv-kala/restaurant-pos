# Task 30.2 - Tax Rules and Rates

## Status

Complete.

## Objective

Provide configurable tenant-scoped tax rates, groups, rules, and menu
category/item mappings.

## Scope Implemented

- `TaxRate`
- `TaxGroup`
- `TaxGroupRate`
- `TaxRule`
- `TaxCategoryMapping`

Not implemented in this task:

- fiscal invoice sequencing
- government integrations
- advanced reports
- shared Dart clients
- UI

## Ownership

- tax rate configuration
- tax group composition
- item/category tax mapping
- rule activation windows

## API

- `POST /tax/rates`
- `GET /tax/rates`
- `GET /tax/rates/:id`
- `PATCH /tax/rates/:id`
- `POST /tax/groups`
- `GET /tax/groups`
- `GET /tax/groups/:id`
- `PATCH /tax/groups/:id`
- `POST /tax/rules`
- `GET /tax/rules`
- `GET /tax/rules/:id`
- `PATCH /tax/rules/:id`
- `POST /tax/category-mappings`
- `GET /tax/category-mappings`
- `GET /tax/category-mappings/:id`
- `PATCH /tax/category-mappings/:id`

## Examples Supported

- GST 5%
- GST 12%
- GST 18%
- CGST 2.5% + SGST 2.5%
- CGST 9% + SGST 9%

## Invariants

- Tax rates store exact basis-point values.
- Tax rate classification fields are immutable after creation.
- Tax groups may contain multiple active rates from the same tax profile.
- Tax rules point to active groups from the same tax profile.
- Active date ranges cannot conflict for the same mapped menu category or item.
- Tenant isolation is enforced through trusted auth scope and forced RLS.
- Mutations use optimistic `version` checks.
- Critical mutations write audit events.

## Dependencies

Requires:

- Task 30.1
- Menu Management
- Billing
- Audit

## Completion Criteria

- Tax rates can be created and listed.
- Tax groups can be created and listed.
- Tax rules can be created and listed.
- Categories/items can be mapped to tax rules.
- Active mapping overlaps are rejected.
- Audit events are generated for configuration mutations.
- Prisma validation, focused tests, and backend build pass.
