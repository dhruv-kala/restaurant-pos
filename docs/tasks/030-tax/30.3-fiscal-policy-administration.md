# Task 30.3 - Fiscal Policy Administration

## Status

Complete.

## Objective

Manage outlet-level fiscal rules and fiscal invoice sequencing.

## Scope Implemented

- `OutletFiscalPolicy`
- `FiscalInvoiceSequence`
- protected fiscal policy APIs
- protected fiscal sequence APIs
- atomic fiscal invoice number generation
- audit events for policy, sequence, and generated number actions

Not implemented:

- government e-invoice integration
- fiscal device integration
- accounting export
- tax calculation engine
- receipt/invoice generation integration
- admin UI

## Ownership

- outlet fiscal year configuration
- invoice prefix configuration
- invoice numbering rules
- outlet-specific fiscal settings

## API

- `POST /tax/fiscal-policies`
- `GET /tax/fiscal-policies`
- `GET /tax/fiscal-policies/:id`
- `PATCH /tax/fiscal-policies/:id`
- `POST /tax/fiscal-sequences`
- `GET /tax/fiscal-sequences`
- `GET /tax/fiscal-sequences/:id`
- `PATCH /tax/fiscal-sequences/:id`
- `POST /tax/fiscal-sequences/:id/generate`

## Invariants

- Fiscal policies are outlet scoped and tenant isolated.
- Active fiscal policy date ranges cannot overlap for the same outlet.
- Fiscal invoice sequences are outlet scoped.
- Fiscal invoice sequence uniqueness is enforced per tenant, outlet, fiscal
  year label, and prefix.
- Generated invoice numbers are monotonic for a sequence.
- Sequence changes and generated numbers are audited.
- Existing receipt invoice generation is not changed by this task.

## Dependencies

Requires:

- Task 30.1 Tax Foundation
- Task 30.2 Tax Rules and Rates
- Task 30.2.5 Tax Architecture Review and Correction
- Outlet Management
- Billing
- Receipt Module
- Audit

## Completion Criteria

- Outlet fiscal policy can be configured.
- Invoice sequences can be created and queried.
- Next fiscal invoice number can be generated atomically.
- Sequence uniqueness is enforced.
- Audit events are generated.
- Build passes.
