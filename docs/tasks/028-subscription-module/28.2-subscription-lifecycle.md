# Task 28.2 - Subscription Lifecycle

## Status

Complete.

## Objective

Manage tenant subscriptions.

## Scope

Implemented:

* TenantSubscription
* TenantSubscriptionEvent
* activate subscription
* upgrade subscription
* downgrade subscription
* suspend subscription
* resume subscription
* expire subscription
* cancel subscription

## Statuses

* TRIAL
* ACTIVE
* SUSPENDED
* EXPIRED
* CANCELLED

`TRIAL` is reserved in the lifecycle model. Trial creation and automatic expiry
remain Task 28.5.

## Invariants

* Every tenant has at most one current subscription in `TRIAL`, `ACTIVE`, or
  `SUSPENDED`.
* Every subscription references an exact Task 28.1 plan-version ID.
* New activations and plan changes require a currently active plan version.
* Previously assigned plan versions remain valid historical references after
  the platform deactivates the catalog version.
* Lifecycle events are append-only and preserve prior/new status and plan IDs.
* Commands use tenant-scoped idempotency keys and optimistic concurrency.
* Tenant subscription records cannot be deleted.
* Tenant subscriptions and events use forced PostgreSQL RLS.
* Only `SUPER_ADMIN` may mutate lifecycle state.
* `TENANT_ADMIN` may read only the authenticated tenant.
* Upgrade and downgrade are explicit platform intent. They are not inferred
  from prices because billing intervals and currencies are not comparable.

## Completion Criteria

* Subscription lifecycle is operational.
* Subscription history is maintained.
* Audit events are generated.
