# Task 28.5 - Trial Management

## Status

Complete.

## Objective

Provide tenant trial subscriptions with time-bound access, immutable history,
expiry handling, and conversion to paid subscriptions.

## Implemented Scope

- Tenant-scoped `TrialSubscription`
- Immutable `TrialSubscriptionEvent` lifecycle history
- Start trial
- Extend trial
- Expire trial
- Expire due trials through a platform-invoked processor endpoint
- Convert trial to a paid `ACTIVE` subscription
- Linked `TenantSubscription` status updates for entitlement behavior
- Platform-only mutation and tenant-admin self-read
- Audit events for all trial lifecycle transitions

## Invariants

- A tenant can have only one trial subscription.
- A tenant can have only one active trial.
- Trial periods are time-bound and must end in the future when started or
  extended.
- Active trials are represented by a linked `TenantSubscription` in `TRIAL`
  status.
- Expired trials update the linked subscription to `EXPIRED`, causing Task 28.3
  entitlement evaluation to fail closed.
- Converted trials update the linked subscription to `ACTIVE` with the paid plan
  version.
- Trial event history is append-only.
- Trial aggregates cannot be deleted.

## API

- `POST /subscriptions/tenants/:tenantId/trials/start`
- `GET /subscriptions/tenants/:tenantId/trials`
- `GET /subscriptions/tenants/:tenantId/trials/:id`
- `GET /subscriptions/tenants/:tenantId/trials/:id/history`
- `POST /subscriptions/tenants/:tenantId/trials/:id/extend`
- `POST /subscriptions/tenants/:tenantId/trials/:id/expire`
- `POST /subscriptions/tenants/:tenantId/trials/:id/convert`
- `POST /subscriptions/trials/expire-due`

`expire-due` is a platform-callable hook for future scheduler integration; no
new scheduler or infrastructure was introduced in this task.
