# Task 34.4 - Retry, Dead Letter, and Recovery Controls

## Status

Complete.

## Objective

Provide bounded retry, dead-letter, and operator recovery controls for failed
background jobs.

## Scope

Implement:

- retry policy configuration by job type
- next-attempt calculation
- dead-letter transition after retry exhaustion
- manual retry action
- cancellation action
- dead-letter resolution record
- protected recovery APIs
- audit events for manual actions

## Deferred

- UI screens
- alerting integrations
- incident management workflows

## Completion Criteria

- Retryable failures are scheduled with bounded backoff.
- Exhausted jobs become dead-lettered.
- Manual retry and cancel actions are authorized and audited.
- Recovery actions preserve immutable attempt history.

## Completion Notes

Implemented in the NestJS outbox module:

- job-type retry policy persistence and protected upsert/list APIs
- bounded exponential backoff calculation for retryable failures
- `DEAD_LETTERED` background job state after retry exhaustion
- tenant/platform scoped `JobDeadLetter` records with forced RLS
- manual retry and cancellation APIs with audit events
- dead-letter resolution API with retained attempt history
- protected read APIs for jobs, attempts, retry policies, and dead letters
