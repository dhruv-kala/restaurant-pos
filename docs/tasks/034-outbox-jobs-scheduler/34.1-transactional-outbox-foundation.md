# Task 34.1 - Transactional Outbox Foundation

## Status

Complete.

## Objective

Create the persistent transactional outbox foundation used by business modules
to record asynchronous work atomically with domain changes.

## Scope

Implemented:

* `OutboxEvent` schema with tenant, optional outlet, event type, aggregate
  reference, idempotency key, payload, status, and timestamps
* platform-scope support for explicitly platform-owned events
* forced RLS for tenant-owned events
* transactional outbox writer service
* idempotency conflict detection
* safe payload redaction helper for logs and audit
* minimal protected read API for authorized operators

## Deferred

* worker execution
* scheduler definitions
* retry/dead-letter controls
* admin UI
* external integrations

## Completion Criteria

* Outbox events can be written inside an existing Prisma transaction.
* Duplicate idempotency keys with different content are rejected.
* Tenant and outlet scope are enforced.
* Tests cover same-tenant visibility and cross-tenant denial.

## Implementation Notes

Task 34.1 added the tenant/platform scoped `OutboxEvent` schema, migration,
forced RLS policy, immutable identity/payload triggers, transactional
`OutboxService.enqueue` writer, safe payload redaction, protected
`/outbox/events` history APIs, permission seeds, and focused unit/schema tests.

Task 34.2 should create background job records and worker claim behavior from
this outbox foundation without changing the outbox event identity contract.
