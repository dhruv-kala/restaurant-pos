# Task 33.3 - Sync Queue and Change Tracking

Status: Complete.

## Objective

Track local changes and queue them for synchronization.

## Scope

Implemented:

* `sync_queue` SQLite table
* `local_change_log` SQLite table
* transactional queue and change-log append
* scoped recovery reads for pending queue items and change-log history

Tracked operations:

* create
* update
* delete

## Invariants

* Queue entries are append-only in this task.
* Local change-log entries are append-only.
* Changes remain recoverable after application restart.
* Tenant, outlet, device, actor, module, entity, operation, business date, and
  payload context are preserved.
* Per-device idempotency keys are unique in the local queue.

## Implementation Notes

Implemented in `apps/restaurant-app/lib/core/offline`:

* schema version 2 creates `sync_queue` and `local_change_log`.
* `OfflineEntityMapper` maps `SyncQueueItem` and `LocalChangeLogEntry` rows.
* `OfflineLocalRepository.appendQueuedChange` inserts the queue item and change
  log entry in one SQLite transaction.
* `OfflineLocalRepository.listSyncQueueItems` and `listLocalChanges` provide
  scoped recovery reads.
