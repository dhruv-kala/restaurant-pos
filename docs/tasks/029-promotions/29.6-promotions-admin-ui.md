# Task 29.6 - Promotions Admin UI

## Status

Complete.

## Objective

Provide tenant administrators with a promotions management interface.

## Scope

Implement:

- Discount Policy Screen
- Coupon Management Screen
- Campaign Management Screen
- Discount Preview Screen
- Redemption History Screen

Do not implement:

- marketing automation UI
- campaign communication composer
- AI offer generation

## Ownership

- promotions administration
- coupon administration
- discount preview
- redemption visibility

## Screens

### Promotions Dashboard

Display:

- active promotions
- active coupons
- redemptions today
- discount amount today

### Coupons

Display:

- code
- type
- validity
- usage count
- status

### Campaigns

Display:

- campaign name
- outlets
- date range
- status

### Discount Preview

Display:

- eligible discounts
- rejected discounts
- rejection reasons

## Authorization

Uses existing lowercase RBAC permission keys:

- `promotions.read`
- `promotions.policy_manage`
- `promotions.coupon_view`
- `promotions.coupon_manage`
- `promotions.campaign_view`
- `promotions.campaign_manage`
- `promotions.eligibility_evaluate`
- `promotions.redemption_view`

## Dependencies

Requires:

- Task 29.1
- Task 29.2
- Task 29.3
- Task 29.4
- Task 29.5

## Implementation Notes

- Shared Dart promotion models were added under `packages/shared_models`.
- A typed `PromotionsApiService` was added under `packages/api_client`.
- `apps/admin` now exposes a Promotions tab for authorized users.
- The admin screen includes dashboard, policies, coupons, campaigns, preview,
  and redemptions tabs.
- Campaign creation is intentionally minimal and creates an all-outlet campaign
  with one initial rule.
- Marketing automation UI, campaign communication composer, AI offers, and
  advanced analytics remain out of scope.

## Completion Criteria

- Promotions UI operational.
- Coupons manageable.
- Campaigns manageable.
- Redemption history visible.
- Flutter analyze passes.
