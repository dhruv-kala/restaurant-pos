# Task 29.1 - Discount Policy Foundation

## Status

Complete.

## Objective

Create the foundation for discount policies and discount calculation rules.

## Scope

Implemented:

- DiscountPolicy
- DiscountApplication
- discount type enums
- discount calculation service
- manual discount permission foundation

Not implemented:

- coupon codes
- campaigns
- loyalty-linked discounts
- admin UI
- redemption tracking

## Ownership

- discount policy storage
- calculation rules
- discount application snapshots

## Data Model

- DiscountPolicy
- DiscountApplication

## Invariants

- Discount calculations are deterministic.
- Discount applications store snapshots.
- Historical bills are not recalculated when policies change.
- Manual discounts require permission checks.
- Tenant isolation is enforced.

## Dependencies

Requires:

- Billing
- Payments
- RBAC
- Audit

## Implementation Notes

Completed on 2026-06-14.

- Added tenant-scoped `DiscountPolicy` and immutable `DiscountApplication`
  snapshot tables.
- Added percentage and fixed-amount discount value support for bill, item, and
  category scopes.
- Added forced PostgreSQL row-level security for both promotion foundation
  tables.
- Added append-only database triggers for discount application snapshots.
- Added NestJS policy CRUD, deterministic calculation, and manual application
  snapshot APIs.
- Added `promotions.read`, `promotions.policy_manage`,
  `promotions.apply_discount`, and `promotions.override_discount` permission
  seed entries.
- Deferred coupons, campaigns, eligibility UI, redemption tracking, and admin UI
  to later Task 29 subtasks.
