# Task 29.3 - Promotion Campaigns

## Status

Complete.

## Objective

Provide time-bound promotion campaigns for restaurants and outlets.

## Scope

Implemented:

- PromotionCampaign
- PromotionRule
- campaign activation/deactivation
- outlet-scoped promotions
- read-only campaign rule evaluation

Not implemented:

- marketing automation
- customer segmentation
- communication sending
- AI promotion generation
- redemption tracking
- eligibility UI
- admin UI

## Ownership

- campaign configuration
- campaign rules
- campaign date windows
- outlet targeting

## Data Model

- PromotionCampaign
- PromotionCampaignOutlet
- PromotionRule

## Campaign Examples

- happy hour
- weekend offer
- festival discount
- new customer offer
- category promotion

## Invariants

- Campaigns are tenant scoped.
- Outlet campaigns cannot apply outside assigned outlets.
- Inactive campaigns cannot produce discounts.
- Expired campaigns cannot apply.
- Rule snapshots are returned by evaluation for future discount application
  snapshotting.

## Dependencies

Requires:

- Task 29.1
- Task 29.2 optional
- Outlet Management
- RBAC
- Audit

## Implementation Notes

Completed on 2026-06-14.

- Added tenant-scoped campaign records with stable per-tenant campaign codes.
- Added selected-outlet targeting through `PromotionCampaignOutlet`.
- Added campaign rules for percentage, fixed amount, free item, category, and
  item promotion types.
- Added campaign activation and deactivation commands with optimistic version
  checks.
- Added read-only active-campaign evaluation for outlet scope, validity windows,
  active rules, currency, and minimum subtotal constraints.
- Added campaign audit events for create, update, activate, and deactivate.
- Added campaign RBAC seed entries:
  `promotions.campaign_view` and `promotions.campaign_manage`.

## Completion Criteria

- Campaigns can be created.
- Campaigns can target outlets.
- Campaign rules can be evaluated.
- Audit events generated.
- Build passes.
