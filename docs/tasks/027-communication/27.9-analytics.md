# Task 27.9 — Communication Analytics

## Status

Complete.

## Objective

Provide operational visibility into communication effectiveness and provider performance.

## Scope

Implement:

* communication metrics
* delivery reporting
* provider performance reporting
* channel reporting

Do not implement:

* BI exports
* AI recommendations
* campaign attribution

## Ownership

* communication KPIs
* provider metrics
* channel metrics

## Metrics

### Delivery

* total messages
* delivered messages
* failed messages
* success rate

### Channel Usage

* email volume
* SMS volume
* WhatsApp volume
* push volume

### Provider Performance

* average delivery time
* failure rate
* webhook latency

## Reports

* communication summary
* provider performance
* channel performance
* delivery trends

## Authorization

Requires:

* COMMUNICATION_VIEW

Administrative visibility:

* TENANT_ADMIN
* SUPER_ADMIN

## Dependencies

Requires:

* Task 27.1
* Task 27.7
* Task 27.8

## Completion Criteria

* Communication KPIs available.
* Provider metrics available.
* Channel metrics available.
* Reporting operational.
* Build passes.

## Implemented

* Tenant/outlet-scoped analytics with a bounded UTC date range
* Daily, weekly, and monthly delivery trend grouping
* Total, delivered/read, failed, pending, and cancelled message counts
* Terminal delivery success and failure rates
* Channel volume, success/failure, and average delivery latency
* Provider volume, success/failure, delivery latency, and webhook latency
* Protected analytics APIs with `communication.analytics_view`
* Shared Dart analytics contracts and typed Dio client
* Riverpod analytics state and date/bucket-controlled admin reporting UI

Analytics are calculated directly from immutable communication messages,
attempt-linked providers, and webhook history. Task 27.9 does not introduce
campaign attribution, BI exports, or materialized analytics tables.
