# Task 27.4 — SMS Delivery Providers

## Status

Complete on 2026-06-13.

## Objective

Implement SMS communication delivery through provider adapters.

## Scope

Implement:

* SMS provider abstraction
* SMS delivery execution
* SMS status tracking

Future provider support:

* Twilio
* MSG91
* TextLocal

Initial implementation may use a single provider.

## Ownership

* SMS delivery
* SMS status tracking
* provider execution

## Supported Use Cases

* OTP
* password reset
* order updates
* delivery status
* operational alerts

## Delivery Status

* PENDING
* PROCESSING
* SENT
* DELIVERED
* FAILED

## Invariants

* Provider credentials never appear in logs.
* Phone numbers are validated before delivery.
* Delivery failures create attempts.
* SMS content is stored as immutable snapshots.
* Retry logic belongs to later tasks.

## Dependencies

Requires:

* Task 27.1
* Task 27.2

## Completion Criteria

* SMS sending works.
* Status tracking works.
* Audit events generated.
* Tenant isolation enforced.

## Implementation

Implemented:

* Twilio SMS provider adapter using the Messages REST API
* E.164 recipient validation
* Twilio account, sender, and Messaging Service validation
* environment-backed auth-token references
* provider-side content-discard and address-obfuscation options
* shared channel-neutral message claiming and attempt execution
* SMS `PROCESSING`, `SENT`, and `FAILED` status tracking
* retryable versus terminal provider failure classification
* redacted SMS delivery audit events

Deferred:

* MSG91 and TextLocal adapters
* automatic retries and background workers
* delivery receipt webhooks
* public resend APIs
* Flutter UI
