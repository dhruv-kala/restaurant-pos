# Task 27.5 — WhatsApp Delivery Providers

## Status

Complete.

## Objective

Implement WhatsApp Business communication delivery.

## Scope

Implement:

* WhatsApp provider abstraction
* template message delivery
* delivery tracking
* read receipt foundation

Future provider support:

* Meta WhatsApp Business
* Twilio WhatsApp

## Ownership

* WhatsApp delivery
* delivery tracking
* read status tracking

## Supported Use Cases

* order confirmation
* order ready
* loyalty notifications
* payment confirmations

## Delivery Status

* PENDING
* SENT
* DELIVERED
* READ
* FAILED

## Invariants

* Only approved templates may be sent.
* Provider credentials never appear in logs.
* Message snapshots remain immutable.
* Read receipts update status only.
* Retry logic belongs to later tasks.

## Dependencies

Requires:

* Task 27.1
* Task 27.2

## Completion Criteria

* WhatsApp messages send successfully.
* Delivery tracking works.
* Read receipt foundation exists.
* Audit events generated.

## Implemented Foundation

* Twilio WhatsApp adapter using the Messages REST API
* E.164 destination and sender validation
* Environment-backed auth-token references
* Approved Twilio Content SID allowlist keyed by immutable internal template
  version ID
* Strict scalar `whatsappVariables` contract
* Internal tenant-scoped `DELIVERED` and `READ` status application service
* `readAt` persistence and provider-message lookup index
* WhatsApp sent, failed, delivered, and read audit events

Public webhook verification and callback endpoints remain Task 27.7.
