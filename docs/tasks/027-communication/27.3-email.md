# Task 27.3 — Email Delivery Providers

## Status

Complete on 2026-06-13.

## Objective

Implement Email communication delivery using provider adapters.

## Scope

Implement:

* SMTP adapter
* Email provider abstraction
* Email delivery execution
* Email status tracking

Future provider support:

* SendGrid
* Mailgun
* Amazon SES

Initial implementation may use SMTP only.

## Ownership

* email delivery
* email status tracking
* email attachments
* provider execution

## Supported Use Cases

* password reset
* user invitation
* invoice delivery
* receipt delivery
* subscription notifications

## Delivery Status

* PENDING
* PROCESSING
* SENT
* DELIVERED
* FAILED

## Invariants

* Provider credentials never appear in logs.
* Rendered content stored as snapshot.
* Delivery failures create attempts.
* Retry logic belongs to later tasks.

## API

Administrative:

* GET /communication/messages
* GET /communication/messages/:id

## Dependencies

Requires:

* Task 27.1
* Task 27.2

## Completion Criteria

* Email sending works.
* Status tracking works.
* Audit events generated.
* Tenant isolation enforced.

## Implementation

Implemented:

* Nodemailer SMTP adapter
* strict SMTP configuration validation and bounded timeouts
* environment-backed provider secret references
* AES-256-GCM recipient-address protection
* atomic queued-message claiming
* append-only numbered delivery attempts
* SMTP acceptance and safe failure classification
* message `PROCESSING`, `SENT`, and `FAILED` tracking
* protected tenant/outlet communication history APIs
* redacted delivery success/failure audit events
* explicit history-view and internal-send permissions

Deferred:

* retry scheduling and workers
* webhook delivery confirmation
* SendGrid, Mailgun, and Amazon SES
* public resend commands
* Flutter UI
* durable attachment storage and retrieval
